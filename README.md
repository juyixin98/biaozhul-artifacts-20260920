# 多边形点定位（pointloc）

纯后端的**带孔多边形点定位**离线计算服务。读取一个 JSON 请求（标准输入），
对一批查询点返回其相对多边形的位置：`inside`（内部）、`outside`（外部）或
`boundary`（边界）。只输出坐标与数值，**不含任何地图或前端**。

判定全部使用**精确整数谓词**（int64 坐标 + `__int128` 叉积），没有浮点
epsilon，也没有“近似重合”。提供两种引擎：

* `naive`：朴素精确判定，逐条边做半开边射线法 + 边界检查；
* `indexed`（默认）：预处理一次的水平条带（slab）索引，适合大批量重复查询。

两种引擎对每一个查询都做同样的精确判定，结果必然一致（测试中逐点比对）。

---

## 1. 构建与运行

环境：g++（C++17，用到 `__int128`）、GNU make；测试另需 Python 3。

```bash
make            # 生成可执行文件 ./pointloc
./pointloc < examples/basic_with_hole.json
```

常用目标：

```bash
make all        # 主程序
make unit_tests # C++ 单元测试可执行文件
make test       # 单元测试 + 差分测试 + 端到端测试
make clean
```

也可显式选择引擎（请求体里的 `"method"`：`"naive"` 或 `"indexed"`，
缺省为 `"indexed"`）。

## 2. 请求 / 响应

### 请求

```json
{
  "method": "indexed",
  "polygon": {
    "outer": [ {"x": 0, "y": 0}, {"x": 20, "y": 0},
               {"x": 20, "y": 20}, {"x": 0, "y": 20} ],
    "holes": [ [ {"x": 5, "y": 5}, {"x": 10, "y": 5},
                 {"x": 10, "y": 10}, {"x": 5, "y": 10} ] ]
  },
  "queries": [ {"x": 2, "y": 2}, {"x": 7, "y": 7}, {"x": 7, "y": 5} ]
}
```

* `polygon.outer`：外环，≥3 个点的数组；首尾点**不要重复**（闭合由程序完成）。
* `polygon.holes`：可选，0 个或多个孔环；每个孔环 ≥3 个点。
* `queries`：可选，批量查询点。省略时进入**仅校验**模式（只做合法性检查）。
* 坐标必须是 JSON 数（整数或有限十进制小数）。环的**顺/逆时针方向不影响结果**。

### 成功响应

```json
{
  "status": "ok",
  "method": "indexed",
  "meta": { ... },
  "results": [
    { "query": {"x": 2, "y": 2}, "location": "inside",  "location_code": 1 },
    { "query": {"x": 7, "y": 7}, "location": "outside", "location_code": -1 },
    { "query": {"x": 7, "y": 5}, "location": "boundary","location_code": 0 }
  ],
  "stats": { "query_count": 3, "index_build_us": 3, "total_query_us": 13,
             "avg_query_us": 4.333333, "bands": 3, "edge_slots": 14 }
}
```

* `location_code`：`1` 内部 / `0` 边界 / `-1` 外部，便于程序消费。
* 查询点按输入顺序原样回显（保留原始数字文本，不做浮点重格式化）。
* 仅校验模式返回 `{"status":"ok","valid":true,...}`。

### 错误响应与退出码

请求结构 / JSON 语法 / 数值范围问题：退出码 `2`；几何不合法：退出码 `1`。

| `error` 码 | 含义 |
|---|---|
| `invalid_json` | 输入不是合法 JSON |
| `invalid_request` | 结构错误（环点数不足、字段类型错等） |
| `invalid_coordinate` | 坐标不是有限 JSON 数 |
| `coordinate_precision_exceeded` | 小数位超过 12 位 |
| `coordinate_out_of_range` | 放大后坐标绝对值超过 4.6×10¹⁸ |
| `invalid_ring` | 某个环本身不合法，`ring_error` 给出细分 |
| `hole_outside_outer` | 孔在外环外 / 触碰外环 / 穿出外环 |
| `holes_intersect_or_nested` | 两个孔相交、触碰或相互嵌套 |

`invalid_ring` 的 `ring_error` 细分：`too_few_points`、`duplicate_point`、
`degenerate_ring`（全部共线）、`self_intersection`（自交/穿顶点/尖刺）。

## 3. 坐标系、精度与取值范围

### 坐标系

坐标定义在**抽象二维笛卡尔平面**上，单位是无量纲的“单位”，**不是经纬度**，
也不做任何投影/大地测量。x 向右、y 向上仅用于描述，判定与方向无关。

### 精度（精确，非近似）

* 输入整数按 int64 精确读入。
* 输入十进制小数按**整个请求统一的比例因子 10^K** 精确放大为整数
  （K = 请求中出现的最大有效小数位数，混写 `1.2` 与 `1.234` 时自动对齐为
  `1200` 与 `1234`，K=3）。响应 `meta.scale` 回传 K。
* 所有定位谓词只做整数加减乘与比较，中间乘积用有符号 128 位整数
  （`__int128`），**不存在浮点舍入误差，也没有 epsilon 容差**。
  三点共线是精确意义上的共线。

### 取值范围

* 有效小数位 **K ≤ 12**；
* 放大后坐标绝对值 **≤ 4.6×10¹⁸**（保证任意一次叉积 `dx·dy2 − dy·dx2`
  都在有符号 128 位范围内且有余量；最大约 6.4×10³⁷ < 1.7×10³⁸）。

> 若坐标确为更大的整数，可在调用前整体平移/缩小；本服务不在内部做有损缩放。

### 环方向

外环顺时针或逆时针均可；孔环也**不要求**与外环反向。面积符号仅用于
退化检测，定位使用方向无关的奇偶规则。

---

## 4. 退化情形的处理

* **边界优先**：每个点先与所有边做“精确共线 + 包围盒内”判定；命中即为
  `boundary`（外环边和孔边都算多边形边界）。
* **水平射线穿过顶点**：采用半开边规则——一条边在
  “恰好一个端点严格位于射线上方”时才参与计数（下端点闭、上端点开）。
  于是射线经过局部最低点时计 2 次、局部最高点计 0 次，奇偶不被破坏。
* **射线沿边的支撑线共线**（点在某条边所在直线上但在边外）：该边不参与
  奇偶计数；点是否在边界上已由上一步确定。
* **水平边本身**不产生纵向交叉。
* **孔内点** → `outside`；**孔边上的点** → `boundary`；
  外环与孔之间的实体区域 → `inside`。

### 合法性校验顺序（先环，后关系）

1. 每个环（先外环，后各孔）：≥3 点；无相邻重复点；
2. 环自交检查（含相邻边尖刺、非相邻边**交叉/穿顶点/部分重叠**全部拒绝）；
3. 环有符号面积非零（在确认无自交后，零面积即全部共线）；
4. 每个孔的**所有**顶点严格位于外环内部（触碰或穿出即拒绝）；
5. 任意两个孔的边界不得交叉/触碰，且不得相互嵌套（只允许互不相交）。

不支持带“岛中岛”的奇偶填充嵌套；需要时请将内层环作为外环另建多边形。

---

## 5. 预处理索引（indexed）

`indexed` 引擎对所有环的边做一次水平条带划分：

* 条数约为 `√(边数)`（上限 4096）；
* 每条边按其 y 跨度登记进覆盖的条带；
* 查询点先过整体包围盒快速判外，再只在其所在条带内做边界检查与奇偶计数。

谓词仍是精确整数运算，索引只减少“看过的边数”，不改变任何判定结果。
20k 次查询、约 2200 个顶点的实测（见下）查询耗时约为朴素引擎的 1/20。

## 6. 自动化测试

* `src/unit_tests.cpp`：C++ 单元测试（精确叉积、共线、穿顶点、环方向反转、
  合法性、带孔定位、大坐标、两引擎 2 万+ 随机点一致性）。
* `tests/differential_test.py`：独立的纯 Python 精确整数参考实现，
  对 `naive` 与 `indexed` 两引擎逐点比对；覆盖固定矩形+孔、菱形穿顶点、
  大坐标、随机凹（星型）多边形多孔、强制取顶点 y、孔边/外边中点、
  环方向反转，以及非法几何拒绝。
* `tests/e2e_test.py`：JSON 入口端到端测试（成功结构、小数统一缩放、
  仅校验、回显原样、各类错误码与退出码）。

运行：

```bash
make test
```

## 7. 实际运行记录

以下为在本机（Ubuntu, g++ 13.3.0, Python 3.12）的真实执行结果。

```

# 干净编译，无 warning；生成 ./pointloc 与 ./unit_tests

$ python3 tests/differential_test.py ./pointloc

$ python3 tests/e2e_test.py ./pointloc

```

索引相对朴素引擎的批查询加速（2200 顶点外环 + 5 孔，20000 查询）：

```
naive    wall=1.33s  query_us=1065904
indexed  wall=0.29s  build_us=137  query_us=52798  bands=47  slots=3240
```

样例请求位于 `examples/`，对应实际输出保存在 `examples/output/`。

### 开发中发现并修复的问题（如实记录）

* 射线“交点在点右侧”的精确比较最初对**下行边**未正确处理分母符号，
  导致凹多边形/孔包含判断错误；已改为方向无关的精确交叉乘法比较
  （`src/geometry.cpp` 的 `rayCrossesRight`），并由差分测试全量守护。
* 自交但**有符号面积恰为 0**的蝴蝶结最初被误报为“全部共线”；
  已将自交检查前移到零面积检查之前。
* 非相邻边对遍历最初漏掉与闭合边相邻的一对，已修正相邻判据。

当前没有已知未通过项。

## 8. 源码结构

```
src/json.hpp/.cpp       无依赖 JSON 解析/序列化（数字保留原始文本）
src/decimal.hpp/.cpp    十进制 -> 统一比例 int64 的精确解析
src/geometry.hpp/.cpp   精确叉积/共线/射线法/256位面积累加/环合法性
src/locator.hpp/.cpp    多边形构建校验、朴素引擎、slab 索引引擎
src/main.cpp            JSON 请求入口、缩放、校验、调度、计时
src/unit_tests.cpp      C++ 单元测试
tests/                  差分测试与端到端测试
examples/               请求样例与实际输出
```
