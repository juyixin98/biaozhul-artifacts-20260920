# tenmem — 受限张量计算图的内存复用规划器与执行器

一个纯本地、合成数据的张量计算图内存复用系统：给定计算图与动态形状上界，
规划缓冲复用，按波次（可并行）执行，校验数值正确性，并在动态形状越界时
拒绝沿用旧缓冲、触发重规划。

技术栈：Python 3.12 · NumPy 2.4 · FastAPI 0.141 · pytest 9。无外部服务、
无真实业务数据，所有输入均为本地确定性合成夹具。

---

## 1. 快速开始（本地验证命令）

```bash
# 依赖（环境已具备时可跳过；版本见 requirements.txt）
python3 -m pip install -r requirements.txt

# 1) 全量测试（断言具体结果与失败类别）
python3 -m pytest tests/ -v

# 2) 覆盖率（要求 >= 80%，当前约 96%）
python3 -m pytest tests/ --cov=src/tenmem --cov-report=term-missing

# 3) 场景矩阵验证（菱形/长寿命/形状突变/并发分支/别名/工作区 + 四类失败）
python3 scripts/verify.py

# 4) 按运行编号重放某次问题（完整 JSONL：输入、波次状态、判定理由）
python3 scripts/verify.py --replay verify-shape-jump

# 5) 启动 HTTP 服务
uvicorn tenmem.api.app:app --app-dir src --host 127.0.0.1 --port 8000
#   GET  /health            健康检查
#   GET  /cases             合成场景列表
#   POST /plan              仅规划，返回缓冲/放置/峰值/无复用基线
#   POST /runs              执行（case= 内置场景，或 graph=+feeds= 自定义图）
#   POST /runs/{id}/release 释放客户端持有的输出
#   GET  /runs/{id}/trace   按运行编号重放结构化记录
```

**预期判断方式**

- pytest：全部 PASSED；覆盖了具体数值断言（对照独立 NumPy 参考实现，而非
  被测核心自证）与具体失败类别断言。
- `verify.py`：退出码 0，表中 11 个场景 `status=ok`，并打印复用峰值 vs
  无复用峰值（复用严格更小）。
- 形状突变场景 `verify-shape-jump` 先出现 `replanning_required` 失败记录、
  再出现 `replan` 记录、最后成功；重规划前绝不向容量不足的缓冲写入。
- 预算超限时规划阶段即返回 `resource_exhausted`（HTTP 507），不会拖到执行中 OOM。

## 2. 模块关系（工程边界）

```
tensor.py      张量类型：dtype、动态维上下界、对齐字节数、Buffer
graph.py       计算图：Node/Graph、两遍结构校验、波次拓扑调度
ops.py         算子注册表：形状推断、数值内核、每算子工作区大小、原地安全标记
planner/
  liveness.py  活跃区间：消费者分析、别名并查集、末消费者安全交接、工作区区间
  memory.py    规划器：波次级贪心放置 + 空闲池最佳适配、峰值核算、字节预算、
               独立的放置冲突后置校验
executor.py    执行器：共享字节缓冲上的波次执行（可线程并行）、逐张量容量
               检查、动态越界→replanning_required、无复用参考执行器、波次轨迹
verification.py 数值验证边界：三方一致性比较（复用/无复用/手写参考）、规划不变量
state.py       训练状态：不可变追加式检查点、恢复/回滚、状态冲突
runlog.py      JSONL 运行日志：运行编号、输入校验和、波次中间状态、判定理由、失败
service.py     编排服务：规划→执行→（越界则重规划）→无复用对照→判定→日志
api/           FastAPI：统一响应信封、错误类别→HTTP 状态码映射、内置场景
fixtures.py    合成夹具：六类图 + 确定性输入 + 各自独立的 NumPy 参考函数
errors.py      错误分类法（跨模块数据/错误契约的单一事实源）
```

依赖方向严格自上而下：`api → service → {planner, executor, verification,
state, runlog} → graph/ops/tensor`，错误类型集中在 `errors.py`。

## 3. 算法假设与关键决策

1. **波次级活跃区间（闭区间）。** 输入/常量在波次 0 出生；节点输出在其
   波次出生；张量在"最后一个消费者所在波次"结束时才死亡。区间为闭区间：
   同一波次内一个生产者与另一个无关消费者可能并行，因此端点相触也算重叠，
   不允许共享——保证同一波次内的节点可任意并行。

2. **两种合法的同缓冲关系，均通过并查组显式表达：**
   - **显式别名**：图声明 `aliases=((out, in),)`，强制共占一块缓冲，区间
     取并集 hull。
   - **末消费者安全交接**：张量在节点 N 处被最后消费，且 (a) 该波次只有
     N 一个消费者（排除并行兄弟竞争）、(b) 算子声明该输入位置原地安全、
     (c) 输入与输出都不是图输出、(d) dtype 与上界容量一致，则输入缓冲直接
     交给 N 的输出。**每节点至多一条交接边**，避免菱形 join 的两个输入经
     输出被传递性合并（二者并行存活，绝不能同址）。

3. **输出在客户端释放前保持存活（pinned）。** 图输出的死亡波次为
   `PINNED`，其缓冲永不回到空闲池、绝不参与任何交接；`release_output`
   显式释放。仍持有输出时再次运行会话属于 `state_conflict`。

4. **动态形状：容量按上界规划，写入前逐张校验。** 规划用声明维上界
   （`(lo, hi)`）确定缓冲容量；执行时具体形状只用于切视图，任何写入前都
   校验 `实际字节 ≤ 缓冲容量`。越界直接抛 `replanning_required`（携带张量、
   实际形状、声明上界、缓冲容量），**中止运行，绝不越界沿用**。服务层据此
   用观测形状重推断静态图、重新规划并重跑；旧计划/缓冲丢弃。

5. **放置算法。** 波次顺序处理；仅当占用者死亡波次严格小于当前波次才回收；
   出生时优先从空闲池取"能容纳的最小缓冲"（best-fit，保留大块给后续需求），
   否则新建。pinned 缓冲永不回收。

6. **对齐与工作区计入峰值。** 所有容量按 64B 对齐（可配置）；算子声明的
   workspace（matmul/softmax 实际使用 scratch，不是名义占用）仅在节点波次
   存活，计入峰值；同波次两个并行节点的工作区必为不同缓冲，后续波次可复用。

7. **峰值口径**：每个波次所有存活"不同缓冲"容量之和的最大值（并查组成员
   共享一块，按缓冲去重）。无复用基线 = 每个张量一块对齐缓冲 + 每个工作区
   一块，全部保留；规划器计算值与无复用执行器实际记账一致（测试逐一核对）。

8. **后置冲突独立校验。** 每个规划返回前，独立于放置过程再次枚举同缓冲上
   的所有占用，验证不同组的闭区间两两不相交。`verification.assert_plan_invariants`
   在测试与 `verify.py` 中再做一遍不依赖规划器内部状态的检查。

9. **数值正确性的三方对照。** 复用执行结果分别对照 (a) 每次全新分配、零
   复用的参考执行器，与 (b) `fixtures.py` 中手写的独立 NumPy 表达式。参考
   答案不由被测核心生成。判定区分：形状不符 / 非有限值 / 超容差 / 缺张量。

10. **并行模型。** 同一波次内的无关节点用线程池执行；规划器对同波次复用的
    禁止性保证意味着并行节点缓冲集合互不相交（NumPy 内核为逐元素/矩阵运算，
    此处仅验证"不共享仍在用的缓冲"这一内存安全性）。

## 4. 错误分类契约（可区分的失败类别）

| category               | 触发场景                                   | HTTP |
|------------------------|--------------------------------------------|------|
| `input_error`          | 图结构非法、缺/多 feed、dtype/rank 不符    | 422  |
| `planning_error`       | 规划器自检发现缓冲冲突（内部不变量破坏）   | 422  |
| `replanning_required`  | 运行时具体形状超过声明上界/缓冲容量        | 409  |
| `state_conflict`       | 输出未释放即重跑、重复释放、未知 run/输出  | 409  |
| `resource_exhausted`   | 峰值需求超过 `max_bytes` 预算              | 507  |
| `computation_failed`   | 数值内核执行期异常（如重规划后仍越源容量） | 500  |

所有错误经统一信封返回：
`{"success": false, "data": null, "error": {"category", "message", "details"}}`。

## 5. 运行日志（可重放）

`logs/runs.jsonl` 每行一条记录，按运行编号串联：
`run_start`（含各输入形状、dtype、校验和、≤64 元素的完整值、规划摘要）→
`run_failure`（失败类别与 details）→ `replan`（原因与新规划）→
`run_trace`（每波次 born/died、存活缓冲 id、容量/实际字节、是否并行）→
`verdict`（逐张量判定理由、最大绝对差、复用/无复用峰值）。
小输入完整记录数值，可据此无歧义重建问题。
