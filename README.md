# 时序计数器重置（counterreset）— 纯后端样例

一个用 Go 实现的**可观测性数据处理后端**教学样例：接收计数器（counter）型时序样本，
在存在**计数器重置、缺样、重复时间戳、乱序到达**的情况下计算区间增长（increase）
与平均速率（rate），并显式输出**估计范围及其成立条件**。

- 纯后端：仅 HTTP JSON API + 本地 JSONL 追加日志持久化，**不含任何前端**。
- 全部数据为合成数据（`examples/seed.jsonl`），不依赖任何真实监控平台。
- 设计语义对齐 Prometheus 的 counter / rate 约定，但**明确区分“严格下界点估计”
  与“需要额外假设才成立的条件上界”**，不对未观察区间做无依据的精确外推。

## 2. 快速开始

要求 Go 1.22+（开发环境为 go1.22.2 linux/amd64）。

```bash
# 运行全部自动化测试（含 -race）
go test -race ./...

# 手算对照（不启动服务，直接打印逐区间结果）
go run ./cmd/handcheck -capacity=100

# 启动 HTTP 服务（默认 :8080，WAL 在 ./data，首次启动加载合成种子）
go run ./cmd/counterreset -addr=:8080 -data-dir=./data -seed=examples/seed.jsonl

# 另一个终端：一键端到端演示（自动挑选空闲端口，输出存 docs/demo-output.txt）
./scripts/demo.sh
```

## 3. HTTP 接口概览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET  | `/healthz` | 健康检查 |
| POST | `/v1/ingest` | 摄入一批样本（整批校验；先持久化后入内存） |
| GET  | `/v1/series` | 列出全部序列及样本数、去重统计 |
| GET  | `/v1/increase` | 窗口增长查询（含区间明细、重置、缺样、估计范围） |
| GET  | `/v1/rate` | 同上，语义共享（`rate = increase / 窗口时长`） |

查询参数：

- `label=k=v`（可重复）或 `labels=k=v,k2=v2`：序列标签
- `start_ms`、`end_ms`：毫秒级 Unix 时间戳，窗口为闭区间
- `extrapolation=none|linear|clamped`（默认 `clamped`）
- `capacity=C`（可选）：计数器容量，给出后才输出**条件上界**

完整字段与请求/响应样例见 [`API.md`](./API.md)。

```bash
curl -sS -X POST localhost:8080/v1/ingest \
  -H 'Content-Type: application/json' \
  --data @examples/ingest-reset.json

curl -sS "localhost:8080/v1/increase?label=__name__=http_requests_total&label=instance=demo-1&start_ms=1700000000000&end_ms=1700000100000&extrapolation=none"
```

## 4. 计算语义（本项目最重要的部分）

### 4.1 输入规则（乱序、重复、负值）

1. **负值直接拒绝**。计数器原始值必须是非负累计值；NaN/Inf 同样拒绝
   （错误码见 `internal/series`：`ErrNegativeValue` / `ErrNonFinite`）。
   一批样本中只要有一个非法，**整批拒绝**（原子性，不做部分写入）。
2. **乱序**：摄入后按时间戳升序排序，不要求按时间顺序发送。
3. **同一时间戳多个值**（max-wins 去重策略）：
   - 值相同 → 幂等重复，只保留一个；
   - 值不同 → **保留最大值**（累计计数器的大值是更“新”的观测），
     冲突数量计入响应与 `/v1/series`，不静默丢弃。
   - 选择 max 而非“后写覆盖”的原因：乱序重传时无法依赖到达顺序，
     而“同时间戳的更大值”在计数器语义下不可能由回退产生（回退即重置，
     会带新的时间戳出现）。

### 4.2 区间增长与重置识别

对相邻观测 `(t1, v1) → (t2, v2)`：

- `v2 >= v1`：无重置，观测区间增量 **下界 = v2 − v1**；
- `v2 < v1`：观测到计数器下降，判定该区间发生**至少一次重置**
  （进程重启 / 外部清零）。观测区间增量 **下界 = v2**
  ——即“上次观测后立即清零”，这与 Prometheus `rate`/`increase`
  的计数器修正做法一致，也正是把计数器重置场景下的结果当**下界**使用的原因。

> 为什么 `v2` 是下界而不是“精确值”？重置可能发生在区间内任意时刻，
> 重置前计数器还可能继续涨了很多（例如 60→200→重置→10：真实增量
> 是 (200−60)+10=150，端点只看到 60→10，按规则只报 10）。

**点估计 `point` 同时就是严格下界 `lower`**：无论缺样区间内部是否隐藏重置，
真实增量都不可能比它小（隐藏重置只会让真实值更大）。

### 4.3 上界：默认没有；给容量才给“条件上界”

- 不提供 `capacity` 时，区间内可能发生**任意次**重置 / 整数回绕，
  真实增量**没有有限上界**，响应中 `upper: null`，并在 `bounds_basis`
  字段用文字说明。
- 提供计数器容量 `C` 后，在**额外假设**“每个观测区间至多重置一次、
  无隐藏回绕”下，区间条件上界为：

  ```
  ub = C − v1 + v2
  ```

  - 实际未回绕：上界为 `v2−v1 + C`（允许它回绕一次）；
  - 实际观测到回绕：上界即 `C − v1 + v2`（重置前最多到 C，重置后到 v2）。

  该上界**只在上述假设下成立**：缺样区间内部若有多次重置，上界即失效。
  这是刻意的诚实性设计——**我们不假装在信息不足时知道上界**。

### 4.4 缺样（gap）：标记，不插补

相邻样本间隔 `> 1.5 × 中位间隔`（`rate.GapFactor`）时标记为 gap：
- 该区间仍只用两个端点计算增量下界；
- **不在缺口内部插值、不虚构增长**；
- 响应 `gaps` 给出起止、间隔、相对中位数的倍数，并提示
  “区间内可能存在未观测到的重置”。

### 4.5 查询窗口边界的三种策略（边界插值策略）

窗口边界往往不与样本点重合。我们**只实现显式、可解释的策略**，
并在响应中返回 `extrapolation_factor`、`observed_coverage` 与 `notes`：

| 策略 | 行为 | 性质 |
|---|---|---|
| `none` | 只累加完全落在窗口内（含端点）的观测区间，**零外推** | 严格的观测下界；`observed_coverage < 1` 时明显偏小 |
| `linear` | 假设窗口内速率处处等于观测区间平均速率，按 `window/observed_span` 线性放大 | 简单启发式；缺口越大越不可信 |
| `clamped`（默认） | 近似 Prometheus `extrapolatedRate`：以平均采样间隔为基准，两端最多各补 1.1 倍平均间隔；边界距离 ≥ 阈值的一端只补半个平均间隔 | 有界启发式，防止长缺口被无限放大 |

无论哪种策略：
- 点估计外推为线性值后仍标记为估计；**线性/截断外推不产生上界**，
  `upper` 在无容量时保持 `null`；
- 速率分母恒为**窗口时长**（而非外推后时长），与 Prometheus
  “先算区间速率再乘窗口秒数”的口径一致。

### 4.6 “不对未观察区间作无依据精确外推”体现在哪

- 缺样区间内部、窗口外区域：从不声称知道真实行为；
- 无容量信息时，上界明确输出 `null` 而不是随便给一个数；
- 有容量时，上界字段与 `bounds_basis` 都写明它依赖的假设；
- 少于 2 个样本时 `point=0` 并附带说明：“这是无观测证据，不代表真实增长为零”。

## 5. 手算验证（验收对照）

运行 `go run ./cmd/handcheck -capacity=100` 可复现下表（输出存档：
[`docs/handcheck-output.txt`](./docs/handcheck-output.txt)）。

### 序列 A：含一次重置 + 一个缺样区间

```
t(s)   0   10   20   30   50   60   70   80   90   100
v      0   10   20   20   30   40   45   60   10    15
                                    └ 30→50 缺样(20s)   └ 80→90 重置(60→10)
```

逐区间下界：

| 区间 | v1→v2 | 增量下界 | 说明 |
|---|---|---|---|
| 0→10 | 0→10 | 10 | |
| 10→20 | 10→20 | 10 | |
| 20→30 | 20→20 | 0 | 持平，不是重置 |
| 30→50 | 20→30 | 10 | **缺样**（中位间隔 10s，此区间 20s，2.0×） |
| 50→60 | 30→40 | 10 | |
| 60→70 | 40→45 | 5 | |
| 70→80 | 45→60 | 15 | |
| 80→90 | 60→10 | **10** | **重置**：只计新值 |
| 90→100 | 10→15 | 5 | |
| **合计** | | **75** | 窗口 100s → 速率下界 **0.75/s** |

条件上界（C=100，每区间至多一次重置）：Σ(100 − v1 + v2) = **915**。
不提供容量：`upper = null`（重置次数未知，上界无限）。

边界策略对照（同一序列，窗口拉长到 [0, 200]，后 100s 无样本）：

| 策略 | factor | increase point | rate（除以 200s） |
|---|---|---|---|
| `none` | 1 | 75 | 0.375（coverage=0.5，诚实偏小） |
| `linear` | 2 | 150 | 0.75（假设后半段同速率） |
| `clamped` | 19/18 ≈ 1.0556 | 79.167 | 0.3958（远端只补半个平均间隔 ≈5.56s） |

### 序列 B：连续两次重置

```
t(s)   0   10   20   30   40   50
v      0   10    2    8    1    5
             重置↑      重置↑
```

逐区间：`10 + 2 + 6 + 1 + 4 =` **23**；速率下界 23/50 = **0.46/s**；
重置 2 次；C=100 条件上界 = 110+92+106+93+104 = **505**；无容量则上界 `null`。

## 6. 持久化（本地样例）

- 每次 `/v1/ingest` 在校验通过后：先向 `data/counter.wal.jsonl` 追加一行 JSON
  并 `fsync`，再更新内存（WAL-only，无快照/压缩，刻意保持简单）。
- 启动时重放 WAL 重建内存；损坏的尾行（崩溃写了一半）跳过并计数，不影响已确认数据。
- 首次启动且数据为空时加载 `examples/seed.jsonl` 合成种子；之后重启只重放 WAL，
  不重复播种。
- 局限（样例项目刻意不做）：无分段/保留策略、无后台 compaction、
  多副本或两阶段提交；WAL 会随摄入线性增长。
