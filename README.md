# 张量内存复用规划（Tensor Memory Reuse Planner）

纯后端、零外部数据/模型依赖的本地机器学习基础设施原型：对**静态张量计算 DAG**
做编译期内存规划，依据每个张量的**最后使用点（last-use）**复用缓冲区，并正确处理
**切片视图的存储别名**。用 NumPy 在可复现的合成数据上验证机制正确性。

- 语言/依赖：Python ≥ 3.10，仅依赖 NumPy（测试用 pytest）
- 支持算子（形状必须全部静态已知）：
  - `add(a, b)`：同形状逐元素加
  - `matmul(a, b)`：二维矩阵乘 `[m,k] × [k,n] → [m,n]`
  - `slice(src, starts, sizes)`：不重叠、铺满基底的矩形切片，产生**零拷贝视图**

## 核心机制

### 1. 时间模型与最后使用点

每个 op 绑定一个整数执行时刻 `time`（要求每时刻至多一个 op，边从早指向晚）。

- 输入在 `time=0` 出生；
- 值 `v` 的活跃区间是半开区间 `[birth, last_use)`：
  - `birth` = 生产它的 op 的时刻；
  - `last_use` = 最后一个读取它的 op 的时刻；图输出（无消费者）存活到程序结束；
- 在时刻 `t`，一个在此刻读完即死的值（`end == t`）与一个在此刻出生的值
  （`start == t`）**允许共享槽位**——执行器保证“先取引用→算出新数组→再写回”，
  写入发生在读取之后，因此即使是 matmul 这类非逐元素算子，端点相接复用也安全。

### 2. 存储组与切片别名

切片视图不复制数据，而是与基底共享同一块物理存储。规划器把
`基底 + 其全部切片`归并为一个**存储组**：

- 组的大小 = 基底大小；
- 组的活跃区间 = 所有成员区间的最小外包（任何视图存活，整块基底都必须存活）；
- 同一基底上的切片必须**互不重叠且恰好铺满**基底（完整划分），构建期强校验；
- 只支持单级别名（禁止“切片的切片”），多级别名需先在图上归并。

### 3. 分配算法

在一整块 arena 上为存储组放置定长槽位，确定性 best-fit：

1. 按出生时刻升序处理；
2. 先回收在本时刻死亡的槽位并合并相邻空闲段；
3. 从空闲段选最小可容纳者（best-fit），放不下则 bump 高水位。

规划同时给出逐时刻物理存活量、峰值时刻与槽位复用链。

### 4. 正确性判据

- **活跃张量不重叠**：任意时刻，同时存活的两个存储组的 arena 地址区间不相交；
- **峰值预算**：物理峰值 ≤ arena 大小 ≤ 预算；
- **结果一致**：复用执行器与“每值一块、切片复制”的不复用基线逐元素相等
  （`max_abs_diff == 0`）。

## 请求格式

```json
{
  "inputs": {"A": [4], "B": [4]},
  "ops": [
    {"name": "C", "op": "add", "inputs": ["A", "B"], "time": 1},
    {"name": "D", "op": "add", "inputs": ["C", "B"], "time": 2}
  ],
  "seed": 42,
  "budget_bytes": 64
}
```

- `time` 可省略，按 `ops` 书写顺序从 1 自动编号；
- 未显式给 `feeds` 时，用 `seed` + 输入名派生子流生成 `[-1,1)` 合成数据，
  同请求结果可复现；
- 无消费者的值自动成为图输出；
- `slice` 用 `src / starts / sizes` 描述。

报告含：每个存储组的 `offset/size/members/alive`、槽位复用链、逐时刻存活量、
arena 峰值、基线对比、最大绝对误差与预算判定。完整样例见
`examples/results/*_report.json`。

## 四个验收场景（实际结果）

数据为 `seed=42` 合成数据；元素均为 `float64`（8 字节）。

| 场景 | 说明 | arena（元素/字节） | 峰值存活 | 累计分配 基线→复用（节省） | 最大绝对误差 |
|---|---|---|---|---|---|
| 01 线性链 | `C=A+B, D=C+B` | 8 / 64 | 8 | 16→8（50%） | 0.0 |
| 02 多消费者 | `A` 被 t1、t3 两次消费 | 24 / 192 | 24 | 40→24（40%） | 0.0 |
| 03 共享视图 | `X(4×4)` 两行切片各与 `P` 矩阵乘 | 34 / 272 | 34 | 56→34（39.3%） | 0.0 |
| 04 分支汇合 | `P` 扇出两分支后 `C=A+B` | 18 / 144 | 18 | 36→18（50%） | 0.0 |

槽位复用链（节选）：

- 01：`A → C → D`（同一 4 元素槽位被三代张量复用）
- 02：`A → E`、`B → D`
- 03：`P → B`（`v,w` 无独立槽位，直接别名到基底 `X` 槽内偏移 0 和 8）
- 04：`P → B → C`、`Q → A`

### 内存口径说明（请先读这一段）

“复用能省多少内存”有两个不同指标，本项目如实分别报告：

1. **峰值同时存活量（peak live）**：生命周期由数据流决定，复用槽位**不改变**
   任何张量的生死时刻。因此在无视图场景，基线与复用的峰值天然相等——复用不能
   让“此刻都还活着”的张量变少；在有共享视图的场景，基线把每个切片复制成独立
   缓冲（峰值 36），复用按物理存储计数（峰值 34），严格更低。
2. **累计分配量（total allocated）**：基线为每个值各申请一块（切片也复制），
   复用只申请单块 arena。这是复用收益无歧义的体现（上表节省 39%~50%），也是真实
   ML 运行时（如静态 arena/planner）的主要省内存方式：把 N 次分配降为 1 块预留。

换言之，本项目的**峰值预算保证**针对的是规划出的单块 arena（物理峰值 ≤ arena ≤
预算）；NumPy 内核在算 `+`/`@` 时会自行临时申请输出数组，进程瞬时 RSS 可能再多
出一个 op 输出，该部分不属于静态规划可保证的范围。

## 限制（明确不支持）

- 仅 `add` / 二维 `matmul` / 单级 `slice`；无广播、无激活函数、无动态形状；
- 切片必须构成基底的完整不重叠划分（保守但使别名分析无歧义）；
- 每时刻至多一个 op（便于精确定义最后使用点；多 op 同时刻需先定序）；
- best-fit 是启发式，不声称对任意生命周期模式达到最优（最优装箱为 NP 难）。
