# ehindex — 磁盘可扩展哈希页索引服务（Rust + Axum）

一个**纯后端**的磁盘可扩展哈希（Extendible Hashing）页式索引，通过 HTTP 提供
键值存取。固定桶容量、目录倍增、桶分裂；删除后做**安全合并与目录收缩**；
哈希函数可注入以**确定性地复现碰撞**；所有结构性变更（分裂链 / 合并）写 WAL，
支持崩溃中断后的幂等恢复。

- 语言/运行时：Rust（edition 2021，实测 1.98.1）
- Web 框架：Axum 0.7 + Tokio（阻塞磁盘操作走 `spawn_blocking`）
- 序列化：serde / serde_json
- 无数据库、无 mmap 依赖，单个自包含索引文件，固定 4096 字节页

---

## 1. 快速开始

### 依赖

- Rust 工具链（含 cargo），1.75+ 即可，开发所用版本为 1.98.1。
- 仅三个直接依赖：`axum`、`tokio`、`serde`、`serde_json`（见 `Cargo.toml`），
  版本已在 **`Cargo.lock` 锁定**（共 55 个传递包，可离线/可复现构建）。

### 构建与运行

```bash
cargo build --release

# 新建并启动（文件不存在时创建；存在则打开并自动崩溃恢复）
./target/release/ehindex \
  --addr 127.0.0.1:8080 \
  --file ./demo.db \
  --cap 4 \
  --hash fx
```

参数（命令行优先，也可用环境变量 `EHINDEX_ADDR / EHINDEX_FILE /
EHINDEX_CAP / EHINDEX_HASH`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--addr` | `127.0.0.1:8080` | 监听地址 |
| `--file` | `ehindex.db` | 索引文件路径（不存在则创建） |
| `--cap`  | `4` | 桶容量（每条记录算 1，范围 1..=6，仅创建时生效） |
| `--hash` | `fx` | 哈希模式：`fx` / `const[:值]` / `mod:n`（仅创建时生效，写入文件头） |

打开已有文件时 `--cap/--hash` 以**文件头为准**；若 `--hash` 与文件记录不一致，
服务拒绝启动（避免用错散列导致定位错乱）。

## 2. HTTP 接口

所有写/读接口请求体均为 JSON（`/raw/put` 除外）。

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| GET  | `/healthz` | — | 健康检查 |
| POST | `/put` | `{"key":"k","value":"v"}` | 插入或更新（upsert） |
| POST | `/get` | `{"key":"k"}` | 查询，不存在返回 404 |
| POST | `/delete` | `{"key":"k"}` | 删除，返回 `existed` |
| GET  | `/stats` | — | 目录/桶/记录统计 |
| POST | `/raw/put?key=k` | 原始字节 | 值为请求体，二进制安全 |

键最大 128 字节、值最大 512 字节（桶页定长 4096 B 决定；容量范围 1..=6）。

### 状态码

- `200` 成功；`400` 请求体非法 / 空键 / 超长；`404` 键不存在
- **`507 Insufficient Storage`**：桶满且分裂无法分离记录（如哈希全碰撞）。
  响应体明确给出原因，例如：

```json
{"error":"桶 0 容量耗尽且无法分裂：桶内全部记录与待插入键的 32 位散列完全相同，分裂无法分离（哈希全碰撞）","kind":"bucket_capacity_exhausted"}
```

### 请求示例

```bash
curl -s  http://127.0.0.1:8080/healthz
curl -s -X POST http://127.0.0.1:8080/put    -H 'Content-Type: application/json' -d '{"key":"k1","value":"v1"}'
curl -s -X POST http://127.0.0.1:8080/get    -H 'Content-Type: application/json' -d '{"key":"k1"}'
curl -s -X POST http://127.0.0.1:8080/delete -H 'Content-Type: application/json' -d '{"key":"k1"}'
curl -s  http://127.0.0.1:8080/stats
```

完整可运行脚本：`examples/requests.sh`；全碰撞演示：`examples/full_collision.sh`。

## 3. 可注入哈希（复现碰撞）

哈希模式记录在文件头：

- **`fx`**：稳定的非加密 32 位散列（FxHash 思路），默认。
- **`const[:值]`**：所有键散列完全相同 → **全碰撞**。桶满后任何分裂都无法
  分离记录，第 `cap+1` 个键立即得到明确的 507 错误，且不会做任何目录倍增。
- **`mod:n`**：`r = fx(k) mod n` 映射到散列**顶端 `ceil(log2 n)` 位**，
  其余位保留 fx 熵。余数相同的键长期聚集在同一目录子树，插入时迫使目录倍增
  与“空转分裂”；但因为低位仍有熵，继续分裂最终可分离。用于复现
  “大量碰撞但可恢复”的真实场景（区别于 `const` 的死局）。

```bash
# 全碰撞：cap=2，第三个键必返回 507
./target/release/ehindex --addr 127.0.0.1:8081 --file /tmp/c.db --cap 2 --hash const
```

## 4. 磁盘布局与算法

单文件、固定 4096 B 页，每个可变页尾部 4 字节 CRC-32（检测撕裂写/损坏）：

```
页 0                  索引头（global_depth、桶容量、哈希模式、空闲链表头、高水位）
页 1                  事务日志元数据（提交点）
页 2                  事务日志描述符表（分裂链中每个最终桶一项）
页 3 .. 26            事务日志镜像区（最多 24 个最终桶页快照）
页 27 .. 1050         目录区（最多 2^20 个 u32 槽）
页 1051 ..            桶页（按桶 id 线性寻址；含 FREE 空闲链表页）
```

### 目录与桶

- 目录是长度 `2^global_depth` 的桶 id 数组；**多个槽可引用同一个桶**
  （桶的 local_depth < global_depth）。
- 槽取散列的**高 global_depth 位** `hash >> (32-global_depth)`，因此同一桶的
  引用槽构成一段**连续且对齐**的块，块大小 `2^(gd-ld)`。

### 插入与分裂链

桶满时沿散列从高到低逐位分裂，直到新键所在叶子桶有空位；若某一位分不开
（新键与该桶全部记录落在同一侧），该次分裂“空转”，继续下一位。
**整条分裂链连同本次插入是一个原子事务。** 当新键与桶内全部记录的 32 位散列
完全相同（或已达最大深度 20）时，返回容量耗尽错误。

### 删除、合并与目录收缩

桶删空后，若伙伴槽块引用的桶 local_depth 相同则等深合并（幸存桶 ld-1、
回收空桶页，回收页进入空闲链表供复用）；伙伴桶已被进一步分裂则本层不合。
幸存桶仍空则沿链继续上合。链结束后，若所有桶都不需要最高位，目录减半
（只改 global_depth；磁盘高半槽成为过期数据，下次倍增覆盖）。

### 崩溃恢复（WAL）

结构变更顺序：

1. 提交前：仅推进高水位 / 倍增目录（倍增是自洽的“槽成对相等”副本），
   **不覆写正式桶页**——此点崩溃不丢任何已提交数据；
2. 把最终桶页写入镜像区、写描述符表、最后写日志元数据并 `fsync` = **提交点**；
3. 提交后才覆写正式桶页、重定向目录槽、回收页，最后清日志。

打开文件时若日志未清，按描述符表**幂等重放**（拷回镜像、必要时倍增、
重定向槽块、回收 FREE、目录收缩）。无日志但发现高水位内的洞页（提交点前
崩溃的孤儿页）会自动回收进空闲链表。

## 5. 自动化测试

```bash
cargo test
```

共 31 个测试（本机全部通过）：

- 单元测试 10 个：CRC 向量、哈希模式与编解码、页头/桶页/日志往返、篡改检测。
- 验收集成测试 17 个（`tests/acceptance.rs`）：
  - **全碰撞** → 明确容量错误（含 const 任意常数）；
  - **分裂中断恢复**：提交前窗口（目录已倍增、日志未写 → 已提交数据不丢、
    孤儿洞页回收），以及提交后三个故障注入点（重定向前 / 重定向一半 /
    清日志前），还有重放幂等（连续重开两次）；
  - **目录共享桶引用**：逐桶校验引用槽数 = `2^(gd-ld)`、连续且对齐；
  - **与内存 HashMap 比对**：4000 次确定性 LCG 混合负载（增/改/查/删），
    逐键 GET + 全量快照一致，重开后再次比对；
  - 删除后的等深合并、目录收缩回 0、回收页复用、**合并中断恢复**；
  - `mod:2` 受控碰撞下的空转分裂与最终分离；
  - CRC 篡改被明确拒绝、哈希模式不匹配拒绝、超长键/值拒绝。
- HTTP 端到端测试 4 个（`tests/http_api.rs`）：随机端口启动真实 Axum 服务，
  覆盖 CRUD、stats、404、507、坏 JSON、空键、二进制安全写入。

故障通过库 API `Index::inject_fault(Fault)` 注入，仅用于测试/验收。

## 6. 一次真实运行记录（release 构建）

- 8 个键（cap=3，fx）→ `global_depth=2, live_buckets=3, total_records=8`；
- 全部删除 → `global_depth=0, live_buckets=1, free_pages=2`（目录收缩、页回收）；
- `const` 全碰撞 cap=2 → 第 3 键 `HTTP 507`，已写两键仍可读；
- 错误哈希模式重开 → `哈希模式不匹配：文件记录为 const:0，启动参数请求 fx`；
- 正确重开 → 历史数据完整（`pending_journal=false`）。

## 8. 范围与未完成项 / 已知限制

- 单进程、单写者：`Mutex<Index>` 串行化磁盘操作（教学/单机服务足够）；
  非多写者并发，也未做 WAL 组提交或页缓存，高并发吞吐不是目标。
- 键/值为定长槽（≤128B / ≤512B），单桶最多 6 条；不支持溢出页/大对象，
  超长键值直接 400。
- 持久化以页 `fsync` 为界，不处理磁盘控制器写缓存丢失等硬件级损坏；
  CRC 能检测但不能修复。
- 全局深度上限 20（目录最大 4 MiB）；达到上限且仍不可分离时报 507。
- 无鉴权/TLS，默认仅监听 127.0.0.1；不要直接暴露到公网。
