# Restricted OWL Class-Expression Service

A pure backend service (Python + FastAPI + SQLite) that reasons over a
**restricted** OWL-style fragment: subclass, equivalence, disjointness and
intersection. It is **not** a full OWL reasoner — every unsupported construct
(union, complement, cardinality, restrictions, SWRL, …) is **explicitly
rejected** with a machine-readable code and a JSON path, never silently
treated as a label.

## Architecture

```
app/
├── language/    rule language: parser + explicit rejection of unsupported constructs
├── kernel/      reasoning kernel: union-find equivalence closure + forward-chaining
│                (EL-style) closure; produces evidence trails for every conclusion
├── oracle/      INDEPENDENT reference: compiles the ontology to propositional
│                clauses and brute-force enumerates finite models. Shares no
│                inference code with the kernel — used to cross-check it.
├── store/       SQLite evidence store: requests, results, processing steps
├── services/    orchestration: parse → reason → cross-check → explainable response
└── api/         FastAPI routes (thin), schemas, dependencies
```

## Reasoning semantics

* **Class unsatisfiable** (`CLASS_UNSATISFIABLE`): a class whose closure
  contains both operands of a disjointness axiom. It is reported with a
  conflict path (two derivation chains + the clashing disjoint axiom).
* **Ontology inconsistent** (`ONTOLOGY_INCONSISTENT`): only when a **named
  individual** witnesses a contradiction. An unsatisfiable class with no
  instances does **not** make the ontology inconsistent — the two states are
  reported separately.
* **Equivalence merging** keeps provenance: each equivalence report lists the
  original declaring axiom sources and the merge chain.
* **Intersection** is compiled to elimination edges (`I ⊑ operand`) plus a
  conjunction introduction rule (`all operands ⇒ I`).
* Unsatisfiable classes entail everything vacuously (ex falso), matching the
  oracle's model-theoretic answer.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/reason` | Classify an ontology; returns consistency, unsatisfiable classes, instances, conflict paths, processing steps, cross-check verdict |
| POST | `/subclass` | Ask whether `sub ⊑ super` is entailed |
| GET | `/requests/{id}` | Retrieve the persisted audit trail of a request |
| GET | `/health` | Liveness + engine version |

Every response carries `request_id` (honors `X-Request-Id` header),
`engine_version`, `failure_categories` (machine-readable) and `uncertainties`
(kept separate from failures). Rejected input returns **422** with
`error.code` and `error.path`.

## Reproduce

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock

# run the independent test suite (75 tests: unit + integration + differential)
.venv/bin/python -m pytest tests/ -q

# start the service
.venv/bin/python -m uvicorn app.main:create_app --factory --port 8419

# or run the full demo (starts the server, runs all fixtures, saves responses)
bash examples/run_demo.sh
```

Demo outputs land in `results/` (kept in the repo for review):
`*.response.json`, `audit_trail.json`, `runtime/service.log`.

## Input format

```json
{"axioms": [
  {"sub": "TA", "super": {"intersection": ["Employee", "Student"]}, "source": "s1"},
  {"disjoint": ["Employee", "Student"], "source": "s2"},
  {"equivalent": ["Admin", "RootUser"], "source": "s3"},
  {"instance": "alice-7", "class": "TA", "source": "s4"}
]}
```

* `source` is optional free text carried into evidence trails.
* Class expressions: IRI string, `{"iri": ...}`, or
  `{"intersection": [expr, expr, ...]}` (≥2 operands).
* Anything else → `UNSUPPORTED_CONSTRUCTOR` / `UNSUPPORTED_AXIOM` / …

## Verification strategy

1. **Unit tests** assert concrete results and failure categories
   (`tests/test_kernel.py`, `tests/test_language.py`).
2. **Independent oracle** (`app/oracle/`) brute-force enumerates finite
   models; `tests/test_oracle_crosscheck.py` checks every fixture node-by-node
   and runs 1200 deterministic random ontologies comparing unsatisfiability,
   consistency, all named subsumptions and instance types. Reference answers
   are therefore *not* generated by the code under test.
3. **HTTP tests** exercise real success and failure paths
   (`tests/test_api.py`), including the 422 rejection path and the audit
   trail endpoint.

## Configuration

All local, no external accounts:

| Env var | Default | Meaning |
|---|---|---|
| `OWL_DATA_DIR` | `./data` | SQLite location |
| `OWL_LOG_DIR` | `./logs` | log file location |
| `OWL_MODEL_CAP` | `100000` | max assignments the oracle may enumerate |
| `OWL_LOG_LEVEL` | `INFO` | log level |
