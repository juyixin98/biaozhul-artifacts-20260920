# 多边形点定位后端 (Polygon Point Location Backend)

纯后端、离线的**带孔多边形点定位**服务。输入多边形与一批查询点（JSON），
返回每个点相对多边形的位置：`inside`（内部）、`outside`（外部）或
`boundary`（边界）。无地图、无前端，输出只有坐标与数值。

- 语言/标准：C++17（仅依赖 Boost.Multiprecision，头文件库）
- 入口：命令行可执行文件 `poly_locator`，读取 JSON 请求（文件或标准输入），
  输出 JSON 响应（标准输出）
- 判定方式：**任意精度整数精确运算**，无浮点、无 epsilon
- 支持批查询、预处理空间索引，并可在同一请求中与朴素精确判定逐点比对

---

## 1. 坐标系、精度与退化处理（明确约定）

### 1.1 坐标系

- 抽象的二维笛卡尔平面直角坐标系（**不是**地理经纬度，不做投影/大地换算）。
- x 轴向右、y 轴向上；面积符号按右手系判定（外环逆时针 CCW 为正）。
- 坐标以 `[x, y]` 数组给出，接受 JSON 数字或数字字符串
  （如 `2.5` 与 `"2.5"` 等价）。

### 1.2 精度（如何做到精确）

1. 请求中出现的每个有限十进制数（多边形顶点 + 查询点）先按字面值解析为
   “符号 × 有效数字 × 10^指数”，**绝不经过 `double`**。
2. 取整个请求的公共放大因子 `10^S`（S = 所有输入中最大的小数位数），
   把每个坐标精确放大为整数。响应中的 `meta.common_scale_exponent` 即 S。
3. 所有几何谓词（叉积、面积、在线段上、线段相交）都在
   `boost::multiprecision::cpp_int` 任意精度整数上完成，不存在舍入。
   因而 10^40 量级下相差 1 的两个点仍可区分（`double` 在此量级已无法表示）。
4. 输出面积、包围盒、回显坐标均为精确有限小数（鞋带公式只产生 ×2，
   故面积最多含一位额外小数）。回显坐标固定保留 S 位小数，以显式表达精度。

限制：输入必须是**有限十进制数**（不接受 `Infinity`/`NaN`）；支持十进制指数
（如 `1e3`），指数绝对值过大将被拒绝。这是计算几何服务，不是任意精度计算器。

### 1.3 退化情形处理

- **点在边界上**：先做边界判定。点严格落在任意边（含端点、水平边）上时
  返回 `boundary`，优先于内/外。边界判定用“叉积为 0 且在包围盒内”，精确。
- **水平射线穿过顶点**：射线法采用半开区间规则——对每条非水平边，
  当且仅当 `min(y0,y1) <= py < max(y0,y1)` 时计数（“含下端、不含上端”）。
  局部极小穿 2 次（不变）、局部极大穿 0 次（不变）、单调经过穿 1 次，
  顶点不会被重复计数。点恰在顶点高度时仍给出正确奇偶。
- **水平边**：永不参与奇偶计数；只通过边界判定处理。
- **环方向（CW/CCW）**：输入方向任意。校验通过后规范化为外环 CCW、
  孔 CW；响应 `meta` 中回显输入方向。查询结果与方向无关。
- **重复相邻点**：自动去除连续重复点（含闭合接缝处）。
- **非相邻重复点、自交（含蝴蝶结/折返重叠）、零面积/共线环**：拒绝
  （见错误码）。环必须是简单环（simple ring）。
- **孔的合法性先校验**：每个孔环自身必须简单；孔的所有顶点必须严格位于
  外环内部（不能压在外环边上或在外）；外环顶点不能落在孔内或孔边上；
  任意两个孔的边不得相交/接触，且孔不得相互嵌套。任一不满足即整体拒绝，
  不返回定位结果。
- **点在孔边上**：返回 `boundary`；点在孔内部返回 `outside`（孔是“挖空”的）。

## 2. 两种定位实现

### 2.1 朴素精确判定（参照实现，naive）

`src/geometry.cpp` 中 `locateNaivePolygon`：

1. 对所有边做精确边界判定；
2. 水平射线 + 半开区间奇偶规则判定相对单环的内/外；
3. 点在外环外 ⇒ 外部；在任意孔内 ⇒ 外部；否则内部。

时间复杂度 O(m)（m 为总边数），作为正确性基准。

### 2.2 预处理索引（slab decomposition）

`src/index.cpp`：以所有顶点的不同 y 坐标划分水平条带（slab），

- 每个条带内，跨越它的非水平边按“条带中线处的 x 交点”用精确有理数比较排序；
- 查询先二分定位条带，再在有序边上二分计数；
- 点的 y 恰在顶点高度时，结合“从该层出发的边”与“跨过该层的边”按同样的
  半开规则计数，并先查顶点/水平边/邻边做边界判定。

查询为 O(log m) 次精确比较级；预处理 O(m·k·log m)（k 为单边跨越的条带数，
最坏 O(m²)，x 单调类多边形接近 O(m log m)）。索引随请求构建（`op=prepare`
可只构建索引并返回统计信息）。

> 两种实现结果在任何情况下必须一致。请求中设置 `"compare_with_naive": true`
> 时，响应每个点同时给出 `location`（索引）与 `naive_location`（朴素）及
> `agree`，并在 `counts.naive_mismatches` 汇总。自动化测试对数十万个随机/边界
> 查询做差分比对，要求零分歧。

## 4. 请求 / 响应

### 4.1 运行

```bash
./poly_locator examples/basic_with_hole.json            # 美化输出
cat req.json | ./poly_locator - --compact               # 标准输入，紧凑输出
./poly_locator --help
```

退出码：`0` 请求被处理（**包括报告多边形非法**）；`2` JSON 语法错误或请求
结构错误。

### 4.2 请求字段

| 字段 | 说明 |
|---|---|
| `op` | `locate`（默认，定位）、`validate`（仅校验）、`prepare`（建索引+统计） |
| `polygon.outer` | 外环：点数组 `[[x,y], ...]`，可开环（末点不必等于首点） |
| `polygon.holes` | 可选，孔环数组；每个为点数组 |
| `points` | `locate` 时必填，批查询点数组 |
| `compare_with_naive` | 可选布尔，返回与朴素精确判定的逐点比对 |

### 4.3 响应

- 成功：`status:"ok"`，含 `meta`（坐标系/运算方式/S/输入环方向）、
  `polygon_stats`（顶点数、孔数、精确面积、外环包围盒）、`results`
  （每点：回显 `point`、`location`，可选 `naive_location`/`agree`）与 `counts`。
- 多边形非法：`status:"invalid_polygon"`，`error` 中给出
  `code` / `where` / `message`。
- 请求错误：`status:"error"`。

### 4.4 错误码

| code | 含义 |
|---|---|
| `MALFORMED_JSON` | JSON 语法错误 |
| `BAD_REQUEST` / `MISSING_POLYGON` / `MISSING_OUTER_RING` / `MISSING_POINTS` / `UNKNOWN_OP` | 请求结构问题 |
| `RING_TOO_SHORT` | 去重后少于 3 个不同顶点 |
| `DUPLICATE_VERTEX` | 环内出现非相邻重复顶点 |
| `SELF_INTERSECTING_RING` | 环的边相交或重叠（简单环要求） |
| `ZERO_AREA_RING` | 退化零面积环 |
| `HOLE_OUTSIDE_OUTER` | 孔有顶点在外环外或压在外环上 |
| `OUTER_TOUCHES_HOLE` | 外环顶点落在孔内或孔边上 |
| `INTERSECTING_HOLES` | 两个孔的边相交或接触 |
| `NESTED_HOLES` | 两个孔相互嵌套 |

## 5. 请求样例

见 [`examples/`](examples/)：

- `basic_with_hole.json` — 方形外环 + 方孔；内部/孔内/孔边/外部
- `vertex_ray.json` — 带 V 形缺口的多边形，射线穿过顶点/缺口尖
- `fractional_request.json` — 小数坐标（S=3），点落在孔边、外环边
- `huge_coords_request.json` — 10^40 量级，相差 1 的点精确区分
- `prepare_index.json` — 多孔多边形，仅预处理建索引
- `invalid_hole_outside.json` — 非法：孔越界

示例：

```bash
./poly_locator examples/basic_with_hole.json
```

```

  decimal.hpp/.cpp   十进制字面量 -> cpp_int，公共放大因子 S

```

## 8. 实测性能（本机，g++ -O2）

下列数字为开发机实测（精确到秒级的命令与结果），仅供量级参考；所有正确性
验证均为“索引结果 == 朴素精确判定”。

- 微基准（8000 顶点 x 单调多边形，200,000 个随机查询）：
  - 朴素精确判定：**约 129 s**
  - slab 索引查询：**约 0.48 s**（查询部分），约 **270×** 加速
  - 建索引（扫描线增量维护）：**约 0.07 s**
  - 简单环 O(n²) 合法性校验（int64/`__int128` 快速路径，超出范围回退
    cpp_int）：8000 顶点约 **2.4 s**
- 端到端 CLI（8000 顶点 + 200,000 查询，含 JSON 解析/输出，3.6 MB 输入/
  9.3 MB 输出）：**约 3.8 s**。
- 大坐标端到端（3000 顶点、S=6 的 1e-6 小数坐标、50,082 个查询，含边中点
  边界点）：`counts.naive_mismatches = 0`。

说明：最坏情况下每条边跨越 O(n) 个条带，slab 存储与建索引为 O(n²)；
x 单调类多边形接近 O(n log n)。本项目是离线后端，优先保证精确与正确，
未实现持久化索引服务（见“不做的事”）。

## 9. 明确不做的事

- 不做地图渲染、前端、可视化、HTTP 服务（本项目是离线计算后端 + JSON 入口）。
- 不做地理坐标投影/经纬度大地测量；坐标是抽象笛卡尔平面。
- 不接受自交环、零面积环、重叠/嵌套/越界的孔（严格校验后拒绝，而非尝试修复）。
