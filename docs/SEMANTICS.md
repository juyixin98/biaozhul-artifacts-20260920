# HTN 规划器语义边界（SEMANTICS）

本文件明确本系统**保证什么、不保证什么**，是判断输出是否可信的依据。
接口返回的三类结论 `success` / `failure` / `inconclusive` 含义不同，
**不可混用**。

## 1. 规则语言

- 事实是基例元组，如 `(road depot port)`、`(at truck1 depot)`。
- **操作符**（名字以 `!` 开头）有 `:pre` / `:del` / `:add` 三段。
- **方法**形如 `(:method 方法名 (复合任务 ?参数...) (:pre ...) (:tasks ...))`。
  方法名是必填的独立符号，用于在失败证据中区分不同候选方法。
- 前置条件是文字合取：正文字、`(not L)`、以及内置比较
  `= != < <= > >=`。比较只对数值求值，对符号求大小关系是语言错误。
- 正文字可以**存在性引入新变量**，例如 `(next ?x ?y)` 会在当前状态中
  为 `?y` 枚举所有匹配，每个求基都是一个独立搜索分支。
- **安全否定**：`(not ...)` 与比较中的变量必须先由参数或更早的正文字
  约束。解析期即拒绝不安全规则。
- `(:tasks a b c)` 是**全序**（顺序链）；部分序写成
  `(:tasks (:partial (t0 t1 ...) (:before i j) ...))`。
  `:before` 只声明被约束的对，未声明的对之间无序。解析期拒绝自环、
  越界索引和约束有环的网络。

## 2. 状态与基本动作

- 世界状态是事实集合。
- 基本动作只有在满足两条时才可执行：
  1. 它在当前残余任务网中是**极小**的（不存在仍存活的前驱）；
  2. 它的**每一条**前置文字在当前状态为真（由内核真实求值，不是名字匹配）。
- 效果按**先删后加**应用：`state' = (state − del) ∪ add`。
- 前置条件在任何效果之前求值；同一动作新加入的事实不会被同动作的删除影响。

## 3. 复合任务分解与方法选择

- 复合任务由方法归约。方法按**声明顺序**尝试，前置条件在**当前状态**
  下求值；多个候选（含存在变量产生的多个求基）按顺序回溯。
- 归约会把被替换任务的外部前/后继边，改接到其子任务网的极小/极大子节点，
  因此跨嵌套层级的次序约束仍然成立。
- 当一个极小复合任务的所有方法都不适用，记录**确定性**死胡同
  `no_applicable_method`，证据逐一列出每个方法名与使其失败的那条文字。
- 全搜索空间被穷尽且无解 ⇒ `failure`。

## 4. “拓扑可排序”不等于“可执行”

这是本系统刻意区分的一点。一个部分序任务网是 DAG，只说明存在拓扑序，
**不说明**存在一个每个动作前置条件都成立的执行序。

判定规则：若残余任务网的所有极小任务都是基本动作，但它们的前置条件
**无一**成立，则该分支是 `deadlock`——既没有可执行动作，也没有可
继续归约的复合任务。典型情形是单一不可重用资源被两个无序任务竞争。

独立验证器（`verify.py`）会从展开树**重建动作位置上的聚合偏序 DAG**，
有界枚举其拓扑序，并对**每一个**线性化从初始状态独立重放：
- `feasible_linearizations` = 前置条件全程成立的线性化数；
- `linearizations_examined` = 实际检查的拓扑序数。

夹具 `docks_two` 是 6 个拓扑序中只有 2 个可执行；`permit_two` 是
2 个拓扑序中 0 个可执行。一个返回“拓扑序”但不重放的检查会错误地
把 `permit_two` 判为可行——本系统明确不这样做。

## 5. 递归与预算（bounds）

递归受多重预算约束，防止不终止分解：

| 预算 | 含义 | 超限结论 |
|---|---|---|
| `max_depth` | 单分支复合任务嵌套深度 | 该分支被剪 |
| `max_expansions` | 全局方法归约次数 | 全局截断 |
| `max_actions` | 单分支基本动作数（动作视界） | 该分支被剪 |
| `max_search_nodes` | 搜索节点数（含回溯） | 全局截断 |

**关键边界语义**：预算被触及时，系统**不得**宣称“无解”。此时结论是
`inconclusive`，原因单列在 `uncertain` 中（`depth_budget` /
`expansion_budget` / `action_budget` / `search_budget`），与确定性的
`failures` 严格分开。同一个问题在更宽预算下可能成功（见夹具
`bounds_walk_long`：`max_depth=1` 为 inconclusive，`max_depth=5` 成功）。

## 6. 非进展循环（cycle）的可靠性条件

只有当**相同的基例复合任务在相同的世界状态下被再次展开**时，才判定为
确定性 `cycle`。理由：方法可应用性是状态的确定函数，相同状态下展开同一
任务必然产生相同子树，属于不可能取得进展的循环。

相同任务但**状态已改变**不算循环（可能是真实推进），交给深度预算，
结论因此是 `inconclusive` 而非伪造的失败。

验证器只独立确认**紧邻**的非进展环：某方法在重放状态下可应用，且其子任务
在不含任何基本动作的情况下立即重新引入同一基例任务。**更深的多步环结构
不在验证器的自动确认范围内**——这种记录会被判为“无法独立确认”，而不是
被默认盖章通过。夹具 `bounds_spin` 覆盖的是紧邻环这一可证情形。

## 7. 展开树

成功结果保留从抽象根网络到基本动作的完整展开树：
- 每个复合节点记录所用方法名、子节点、以及子节点间的次序（全序链或
  声明的 `:before` 边）；
- 每个叶子记录实际执行的操作符与实参；
- 父子关系显式保存，可从任一动作回溯到它所属的抽象任务与方法链。

失败结果**没有**成功展开树（搜索未到达终态）；此时证据以“失败分支”
形式给出（动作前缀 + 残余任务网快照 / 被拒方法），而不是伪造一棵树。

## 8. 独立验证器做什么、不做什么

验证器**不导入、不复用规划搜索引擎**，它独立完成：

1. **可执行性**：从问题初始状态独立重放动作序列，逐条核对操作符前置条件。
2. **层级一致性**：对每个展开节点，核对方法真实存在、子任务头与方法定义
   一致、叶子与动作序列一一对应、且各子树叶子的执行位置满足声明的次序。
3. **次序一致性**：重建聚合偏序，检查无环、计划是其一个线性化，并枚举
   重放所有（有界）线性化。
4. **失败佐证**：对失败结果，重放其动作前缀到达所声称的状态，然后
   - `no_applicable_method`：独立确认所引方法在该状态下确实全部不适用；
   - `deadlock`：从快照边重算极小集，确认每个极小动作/复合任务都被卡住，
     并重算每条被引为“未满足”的前置条件确实为假；
   - `cycle`：按第 6 节的紧邻环条件独立确认。
5. 对 `inconclusive`，验证器明确给出 `inconclusive_not_verifiable`，
   **不**把它当成功也不当已证失败。

### 验证器的能力边界（明确不保证）

- 线性化枚举上限为 `MAX_LINEARIZATIONS = 5000`。超过时
  `linearizations_truncated=true`；这意味着“未在已枚举部分找到可行序”
  不能外推为“绝无可行序”。当前夹具都远小于该上限。
- 深层（非紧邻）循环不自动确认，见第 6 节。
- 验证器只核对**返回的**计划/证据与领域、问题、状态是否一致；它不重新
  做一次无界的完备搜索，因此不能替代预算本身的作用。
- 谓词/操作符语义限于本语言（集合状态、先删后加、内置比较）；不含数值
  流、外部过程或时间度量。

## 9. 失败类别一览

| category | 含义 | 确定性 |
|---|---|---|
| `no_applicable_method` | 极小复合任务无任何适用方法 | 是 |
| `deadlock` | 极小任务全为基本动作且前置条件全假 | 是 |
| `cycle` | 同任务同状态的非进展重复 | 是（紧邻环） |
| `depth_budget` | 触达深度视界 | 否（不确定） |
| `expansion_budget` | 全局展开次数耗尽 | 否（不确定） |
| `action_budget` | 单分支动作视界耗尽 | 否（不确定） |
| `search_budget` | 搜索节点数耗尽 | 否（不确定） |

## 10. 不在本环境执行的检查

以下检查**没有运行**，因此在任何报告中都不得写成“已通过”：

- 需要生产账号、真实业务数据或对外网络的部署/鉴权/压测；
- 超大规模负载测试（夹具是小规模合成数据，搜索刻意有界）；
- 未建模语言特性（外部动作、时间、资源数值核算）上的性质。
