## 3. 三场景验收数字

命令：

```bash
PYTHONPATH=src python3 -m sudden_anomaly.cli --scenario all --out-dir out
```

默认配置：`threshold=5.0 window=512 prime=64 min_history=16 recent=32
shift_persist=3 scale=mad center=median`，采样率 100 Hz，每场景 2000 点，σ=1。

| 场景 | 真值位置 | 命中 | 首次检出延迟 | 误报数 | 报警点数 |
|---|---|---|---|---|---|
| 阶跃（+6σ，@1000 持续） | 1000..1999 | 100% | **0 点（0 ms）** | 0 | 248 |
| 漂移（0.004/点，@1000 起） | 1000..1999 | 100% | **451 点（4510 ms）**，检出点 1451 | 0 | 65 |
| 孤立尖峰（+12σ @ 400/900/1500） | 三个单点 | 100% | **0 点（0 ms）**，全部命中真值点 | 0 | 恰好 3 |

说明：

- 阶跃由 `pulse_score` 在变化当点直接捕获，因此 0 延迟；其后持续报警直到
  双窗基线跟踪到新水平（属预期自适应行为）。
- 漂移在累计偏移约 1.8σ 处才被分组位置统计识别。**缓慢漂移的延迟是固有的**：
  偏移仍与噪声同量级时，任何只用过去样本的方法都无法可靠区分。这不是失败项，
  而是因果检测的物理边界，已在 README 第 9 节声明。
- 孤立尖峰恰好产生 3 个报警，没有向相邻样本拖尾（稳健 MAD + 脉冲统计只对当点）。

## 4. 逐块 / 逐点一致性

独立脚本对三场景分别以块大小 `{1, 37, 137, 512, 10000}` 分块，与一次性处理
逐点比对 `decisions`、`scores`（NaN 归一后）、`anomaly_indices`：

```
block-vs-oneshot parity across bs in {1,37,137,512,10000}: IDENTICAL
```

PCM 文件模式同样比对一次性与 `--block-size 100` 的逐点 CSV 判定列：

```
PCM CSV decisions IDENTICAL
```

一致性由结构保证而非偶然：`feed()` 对任何输入都 reshape 后逐点调用唯一的标量
路径 `_feed_scalar()`，分块只是多次调用并 `_stitch` 拼接。

## 5. 误报率（蒙特卡洛实测）

干净高斯噪声、默认配置：

| 轮次设置 | 可判样本 | 误报 | 误报率（/千点） | 出现过误报的轮次 |
|---|---|---|---|---|
| 120 轮 × 4000 点（干净） | 472,320 | 2 | **0.0042** | 2/120（各 1 个） |
| 40 轮 × 4000 点（5% 缺样） | — | 1 | — | — |

对照：高斯 5σ 双侧理论尾概率约 0.0006/千点；稳健统计在有限样本尺度估计下实测
略高，但已是很低的水平。另设固定种子 2 万点回归测试（0 误报），任何抬高误报
的改动都会令 CI 失败。

## 8. 开发中出现过的未通过项（如实记录）

首轮 `./run_tests.sh` 并非全绿，出现 **2 个失败 + 5 个错误**，全部定位、修复并
复测通过：

1. **算法缺陷：单窗 z 分数检测不到缓慢漂移（最重要的一项）。**
   初版只用"当前点 vs 滑动窗"的稳健 z 分数。实测 `drift` 场景命中率 0：
   单调漂移被窗口自身的中位数/MAD 吸收，z 始终不大。
   *修正*：新增因果**双窗位置统计**（近期短窗中位数 vs 更早基线窗中位数，按
   中心的合并渐近标准误归一化），脉冲仍由原统计负责；漂移由此可检（延迟 451）。
   并据此把默认窗口调为 512、近期窗 32（经 W∈{256,512,1024}×R∈{16,32,64}
   的网格实测：R=16 时短窗噪声尾端会产生误报，W=512/R=32 全面良好）。

2. **`_stitch` 变量名 bug（影响所有分块路径）。**
   拼接函数中 `np.concatenate([r.scores])` 误用了上一个推导式泄漏的循环变量
   `r`，触发 `UnboundLocalError`，导致所有 `--block-size` 分块运行和 3 个 parity
   测试报错。*修正*：所有拼接改为显式列表推导
   （`[x.scores for x in results]`，循环变量改名 `res`）。

3. **误报率偏高：0.132/千点（单轮最多连发 18 个）。**
   初版双窗统计把仅 32 点的近期窗 MAD 也并入分母，短窗尺度估计噪声大、比值
   重尾；且重叠窗中心高度相关，一次波动在多点重复超阈。
   *修正*：尺度只取自样本量更大的基线窗；位置报警增加连续 `shift_persist=3`
   确认（脉冲不设持续性，保持尖峰 0 漏检延迟）。修正前后用同一套原型在 60 轮
   干净噪声上对照：稳定尺度方案从最高 0.08/千点降到 0/千点（原型），真实
   检测器 120 轮复测为 **0.0042/千点**，且不再成串。

4. **测试笔误（非产品 bug）：** 缺样用例断言 `n_observed[5]==0`，但索引 5 已是
   观测样本（NaN 只覆盖 0..4），改为 `[4]`。

5. **CLI 缺样场景文件名变化：** 注入缺样后场景名变为 `spikes_missing`，测试仍
   读 `spikes_summary.json` 而失败；测试改为读取实际文件名。

6. **`n_observed` 计数时点：** 修复中发现该值在样本折入窗口"之前"记录，导致
   "缺口后计数"断言差 1。统一为在更新后报告当前已观测样本总数。

修复后 39/39 通过，且本报告第 3–6 节的端到端数字均为修复后复测所得。
