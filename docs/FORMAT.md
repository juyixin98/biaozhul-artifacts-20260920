# CDCT 二进制格式规范（版本 1）

CDCT（**C**olumnar **D**ictionary **C**oding for **T**ext columns）是面向
字符串列的流式字典编码二进制格式。本文档是权威格式定义，实现见
`src/segment.rs`。

## 1. 总体结构

```text
file := magic version segment*

magic   := 0x43 0x44 0x43 0x54              // ASCII "CDCT"
version := 0x01                              // uint8，当前为 1
segment := seg_magic dict_count row_count
            dictionary_block
            id_block

seg_magic := 0x53 0x45 0x47 0x4D            // ASCII "SEGM"
```

* 文件以 4 字节魔数 `CDCT` 开头，后接 1 字节版本号。
* 随后是零个或多个**段（segment）**。文件允许包含零个段（空列）。
* 除固定魔数外，所有整数均为 **无符号 LEB128（varint）**（见 §2）。
* 所有长度均以**字节**计，多字节字符串使用 UTF-8 编码。

## 2. 整数编码（LEB128）

每个字节低 7 位承载数据，最高位为"续位"：

* 续位为 1：后续还有字节；
* 续位为 0：本字节是最后一个。
* 数据按小端序拼接。u64 最多 10 字节，第 10 字节只允许最低 1 位有效。

示例：

| 值 | 字节 |
|---:|---|
| 0 | `00` |
| 1 | `01` |
| 127 | `7f` |
| 128 | `80 01` |
| 16384 | `80 80 01` |

## 3. 段结构

### 3.1 段头

```text
seg_magic   4 字节，固定 "SEGM"
dict_count  varint，本段字典条目数 D（可为 0）
row_count   varint，本段行数 R（可为 0）
```

### 3.2 字典块

紧跟 `dict_count` 个字典条目，每个条目：

```text
entry := byte_length:varint utf8_bytes[byte_length]
```

* 条目按**首次出现顺序**排列（编码端的插入序）。
* 条目允许为空串（长度为 0）。空串与 NULL 是两个不同的值。
* 字节内容必须是合法 UTF-8，否则解码报错。
* 条目不要求全局唯一去重，仅要求段内语义一致；标准编码器保证段内不重复。

### 3.3 ID 块

紧跟 `row_count` 个行 id，每个 id 为一个 varint：

| id | 含义 |
|---:|---|
| `0` | **NULL**（保留值，独立于字典存在） |
| `n >= 1` | 引用本段字典第 `n - 1` 个条目（0 基下标） |

* id 必须满足 `id <= D`，超出则解码端返回 `BadReference` 错误。
* 全 NULL 段的 `D = 0`，字典块为空，不依赖任何字典条目表达 NULL。
* id 使用 u32 语义空间（单段字典上限约 42.9 亿；实际受 `Limits` 约束）。

## 4. 分段与合并

* 编码器可按固定行数 `segment_rows` 将一列切成多段；每段拥有
  **独立的本地字典**，id 从 1 重新编号。
* 分段使内存峰值与单段规模（而非整列规模）成正比。
* 合并多个输入流时，合并端构造一个**全局字典**（首次见到的新值追加），
  并为每个输入段建立 `本地 id -> 全局 id` 的重映射表：

  ```text
  remap[0] = 0                       # NULL 始终映射为 NULL
  remap[i + 1] = global_id(local_dict[i])
  ```

  每个输出行 id 经该表翻译后写出。
* 输出段携带写出时全局字典的**快照**。跨输出段重复携带字典换取流式处理：
  合并端无需读入全部数据即可产出结果，且输出仍是自描述的。
* **字典顺序无语义**：id 始终在同段字典的命名空间内解释。任意重排字典并
  同步改写 id，解码结果逐行完全一致。合并改变 id 编号不影响解码值。

## 5. 内存与输出长度限制

实现通过 `Limits`（见 `src/error.rs`）在读取过程中逐项检查，任何越界都在
分配/产出前中止并返回 `LimitExceeded`：

| 限制 | 默认值 | 检查点 |
|---|---:|---|
| `max_dict_bytes` | 256 MiB | 插入/读取每个字典条目时累计 |
| `max_dict_entries` | 10,000,000 | 新插入前、读取声明计数后 |
| `max_rows` | 10,000,000 | 段内行数与合并累计行数 |
| `max_string_bytes` | 16 MiB | 单字符串长度 |
| `max_decoded_string_bytes` | 512 MiB | 解码输出字符串字节累计 |
| `max_segments` | 10,000 | 段计数 |

流式特性：

* 编码：内存 = 当前段字典 + 当前段 id 缓冲；段满即刷写到输出。
* 解码：内存 = 当前段字典；行可经回调逐条消费，不必物化整列。
* 合并：内存 = 全局字典 + 一个输入段字典 + 一个输出段 id 缓冲。

## 6. 错误与健壮性

解码端必须拒绝以下输入（错误类型见 `Error`）：

1. 文件魔数或版本号不匹配 → `Invalid`；
2. 段魔数错误（含段后残留垃圾）→ `Invalid`；
3. 任何 varint / 长度 / 字节块在流中提前结束 → `Truncated`；
4. varint 超过 10 字节或超出 u64 → `Invalid`；
5. 字典字节不是合法 UTF-8 → `Invalid`；
6. 行 id 超出本段字典范围（悬空引用）→ `BadReference`；
7. 超过任一 `Limits` → `LimitExceeded`。

## 7. 设计取舍备注

* 字典块每段重复：格式简单、可流式合并、任意切分点可独立解码，代价是
  高基数数据下段间冗余。需要更高压缩率时可在段块之上再套通用压缩层
  （本格式刻意不含该层）。
* id 采用 varint 而非定长 4 字节：小字典下 id 通常 1–2 字节，大字典退化
  时仍可扩展到 u64 表示。
* NULL 用保留 id 0 而非字典哨兵：空串、NULL 与任意普通字符串三者互不
  混淆，全 NULL 段零字典开销。
