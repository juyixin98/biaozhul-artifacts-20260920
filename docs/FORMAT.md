# LZSW 二进制流格式规范（版本 1）

本文档是 LZSW 压缩流格式的唯一权威定义。所有多字节整数均为**小端序**。

## 1. 总体结构

```text
+------------------+-----------------------------+
| 头部 (12 字节)    | token 流（直至输入结束）      |
+------------------+-----------------------------+
```

## 2. 头部（12 字节）

| 偏移 | 长度 | 字段       | 说明                                          |
|------|------|-----------|-----------------------------------------------|
| 0    | 4    | magic     | 固定为 ASCII `LZSW`（`4C 5A 53 57`）           |
| 4    | 1    | version   | 格式版本，当前为 `1`                           |
| 5    | 1    | flags     | 保留标志位，必须为 `0`                         |
| 6    | 2    | window    | 滑动窗口大小（u16 LE），1..=65535，最大合法回距 |
| 8    | 2    | max_match | 最长匹配长度（u16 LE），本版本固定为 `130`     |
| 10   | 2    | reserved  | 保留，必须为 `0`                               |

头部任一字段不满足约束时，解码器必须拒绝整个流。

## 3. Token 流

头部之后是连续的 token 序列，直到压缩数据结束。每个 token 以 1 字节
控制字（control byte）开头，由最高位区分两类：

### 3.1 字面量 token（控制字最高位为 0）

```text
+-----------+----------------------+
| 0LLLLLLL  | L+1 个原始字节        |
+-----------+----------------------+
```

- 低 7 位 `L` 表示长度减 1，故字面量长度 `len = L + 1`，范围 1..=128。
- 紧随其后是 `len` 个未压缩的原始字节，原样拷贝到输出。

### 3.2 匹配 token（控制字最高位为 1）

```text
+-----------+--------------------+
| 1LLLLLLL  | distance (u16 LE)  |
+-----------+--------------------+
```

- 低 7 位 `L` 表示匹配长度偏移：`len = L + 3`，范围 3..=130。
- `distance` 为回距（u16 LE）：从当前输出位置向前回退的字节数。
- 语义：把已输出序列中 `distance` 字节之前开始的 `len` 个字节追加到输出。

## 4. 解码规则与合法性约束

解码器必须逐 token 执行以下校验，任一不满足即报错并终止：

1. **回距非零**：`distance >= 1`。
2. **回距不超窗口**：`distance <= window`（头部声明值）。
3. **回距不越过已有输出**：`distance <= 已输出字节总数`。即引用不得
   指向输出起点之前（流开头不得出现匹配 token，除非已有足够输出）。
4. **重叠复制**：允许 `len > distance`。此时逐字节拷贝，刚写出的字节
   立即可被后续拷贝引用。例：输出 `ab` 后，`(distance=2, len=10)`
   产生 `ababababab`，总输出 `abababababab`。
5. **完整性**：输入必须在 token 边界处结束。头部不完整、字面量字节
   不足、回距缺字节，均为截断错误。
6. **输出预算**：解码器配置输出预算 `max_output`（默认 16 MiB）。
   任一 token 发射前若 `已输出 + 本token长度 > max_output`，必须报
   `output_limit_exceeded` 并终止——这是压缩炸弹防护。

## 5. 编码器行为（参考实现）

- 贪心匹配：在每个位置用 3 字节哈希链在窗口内搜索最长匹配
  （链深上限 32），匹配长度 ≥ 3 则发射匹配 token，否则发射字面量。
- 字面量积累到 128 字节即冲刷为一个字面量 token。
- 流式不变量：非收尾时保留末尾 129（`max_match - 1`）字节不编码，
  因为从此处开始的匹配可能被后续输入延长。因此**编码结果与输入
  分块方式无关**。
- 内存有界：窗口历史 ≤ `window` 字节，哈希表固定约 384 KiB
  （2^15 个头指针 + `window` 个链节点），与输入总长无关。

## 6. 解码器资源上界

- 历史缓冲：`window` 字节（环形，超出即丢弃最旧字节）。
- 当前 token 缓冲：≤ 130 字节。
- 输出：由调用方缓冲，受 `max_output` 预算硬约束。
